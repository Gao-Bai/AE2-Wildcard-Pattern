# v2.3.0 — 匹配器搜索与标签反查修复

本版只修界面里的搜索/反查，**不需要重建已有样板**：直接替换 jar 即可，旧规则与旧样板完全兼容。

前置要求不变：Minecraft 1.20.1、Forge 47+、**Applied Energistics 2 15.x 必需**，JEI 15.x 可选。

## 修了什么

**1. 标签模式列出了"空气 / 石头 / 花岗岩"**
原来查询没有命中时会回退成「列出该类型的所有条目」，物品模式下那就是注册表前 256 个物品 —— 看起来像过滤器失效。
现在：只在**查询为空**时列出该类型供浏览；有查询但没命中时，只保留「使用输入的内容」一行。

**2. `gtceu:single_wire` 搜不到细导线**
搜索原本是整串子串匹配，而实际物品是 `gtceu:tin_single_wire`。现在按 `:` `/` `_` 与空格**分词**匹配，
`gtceu:single_wire`、`single wire` 都能命中；标签列表同样支持分词。

**3. 只能搜索、不能直接输入**
结果列表里新增「使用输入的内容」一行（形如 id 的输入排在最前、普通词排在最后），
选中回车即可把原样的标签 / 物品 id 作为规则，例如直接输入 `forge:wires/tin`。

**4. 选中物品后无法反查它属于哪些标签**
现在点过某个物品后再切到 `#标签`（或 `族通配`），会列出**那个物品**所属的标签 / 族：
`gtceu:tin_single_wire` → `forge:wires/tin`、`forge:wires/*`。这也是做「任意锭 → 细导线」这类通配样板的正确入口。

**5. 物品名显示成 `%s锭`**
格雷科技这类按材料拼名字的模组用的是复合翻译键，原来用 `Component.translatable(getDescriptionId())` 只会拿到模板。
现在改用 `stack.getHoverName()`，显示正常名称。

**6. 状态行文字被截断**
状态行现在只显示「将生成 N 条，排除 M 条」和页码（还有更多内容时显示 `...`），
**鼠标移上去**用 tooltip 显示完整内容：前几条会生成的配方 + 警告 + 报错/提示。

## 升级说明

- 直接替换 `mods/` 里的旧 jar 即可；规则存在物品 NBT 里，不受影响；
- 如果你之前为了搜到某个标签而手工输入过它的完整 id，本版依然支持（见第 3 条）。

## 已知限制

与 2.2.0 相同：NBT 精确匹配、可选输入默认关闭（开启上限 2 层）、`@模组` 匹配器默认关闭、
返回槽依赖机器主动弹出、单张样板默认最多展开 256 条配方。
