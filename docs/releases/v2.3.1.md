# v2.3.1 — 匹配器搜索与标签反查修复

只改界面里的搜索/反查逻辑，**旧规则与旧样板完全兼容**，直接替换 jar 即可。

## 修了什么

**1. 标签模式列出了"空气 / 石头 / 花岗岩"**
查询没有命中时，旧逻辑会回退成「该类型的所有条目」，物品模式下那就是注册表前 256 个物品。
现在只在**查询为空**时列举该类型供浏览；有查询但没命中时显示「没有匹配项」。

**2. `gtceu:single_wire` 搜不到细导线**
真实物品 id 是 `gtceu:<材料>_single_wire`（如 `gtceu:black_steel_single_wire`），而搜索原本按整串子串匹配。
现在按 `:` `/` `_` 与空格**分词**匹配：`gtceu:single_wire`、`single wire` 都能命中所有材料的导线；标签列表同样支持分词。

**3. 「使用输入的内容」会建出空规则**
这一行在 2.3.0 里总是出现并默认选中，输入不存在的 id 回车就会得到一条匹配不到东西的规则。
现在只有**目标真实存在**时才提供：物品查得到、标签存在、族通配以 `*` 结尾或能查到别名。图标也从 `*` 改为 `+`。

**4. 选中物品后无法反查它属于哪些标签**
点过某个物品后再切到 `#标签`（或 `族通配`），会列出**那个物品**所属的标签 / 族。
例如 `gtceu:black_steel_single_wire` → 它登记的导线标签（如 `forge:wires/black_steel`）。
这也是做「任意锭 → 对应材料线材」这类通配样板的入口。

**5. 物品名显示成 `%s锭` / `1x铝导线`**
格雷科技这类模组用复合翻译键拼名字，旧代码只拿到模板；现在用 `stack.getHoverName()`，
并去掉 `includeAmountInItemName` 带来的 `1x` 前缀。

**6. 状态行文字被截断**
状态行只显示「将生成 N 条，排除 M 条」与页码，有更多内容时显示 `...`；**鼠标移上去**用 tooltip
显示完整内容（前几条配方 + 警告 + 报错/提示）。

## 一个使用提示（任意锭 → 线材）

1. 原料：族通配 `ingot*`，组 `A`；
2. 产物：先在`物品`模式搜 `single wire` 选中任意一种导线 → 切到 `#标签`，列表里会给出它所属的导线标签，
   选一个（若想覆盖所有厚度就选 `族通配` 里的 `forge:wires/*`），组同样设 `A`；
3. 编码后装进供应器：黑钢锭 → 黑钢导线、铜锭 → 铜导线……

> 如果你那边 `#标签` 里看不到导线标签，说明当前格雷版本没有给线材登记物品标签 ——
> 那种情况下需要「按物品 id 里的材料名配对」的新匹配器，请开 issue 说明。

## 已知限制

与 2.2.0 相同：NBT 精确匹配、可选输入默认关闭（开启上限 2 层）、`@模组` 匹配器默认关闭、
返回槽依赖机器主动弹出、单张样板默认最多展开 256 条配方。
